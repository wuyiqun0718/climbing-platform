# 项目背景与进度

最后更新：2026-10-17。这份文档记录了从最初需求到现在的所有关键决定，换电脑、换账号后从这里接着做。

## 1. 背景

- 要给 BENCHMARK 攀岩馆做微信小程序（会员端）和管理后台（门店端）。
- 第一步是做一个能点的原型，拿去给老板演示、谈合作；谈下来再做正式版。
- 长期目标是做成多岩馆平台：一个仓库里放多家岩馆的小程序和后台，共享组件、工具和服务，每家可以单独打包。
- BENCHMARK 有三家店：**滨港店、汇聚店、环球港店**。

### 品牌

- 标志是一只抱着岩板的树懒，配 BENCHMARK 手写字。原图在 `gyms/benchmark/assets/logo.jpg`，去掉绿底的版本是 `mark.png`。
- 颜色全部取自标志：橄榄绿 `#86972F`、米色木板 `#E9D1AD`、灰色岩板 `#C4C3C8`、黑色描边、白色。
- 设计语言：2px 黑描边、硬投影、斜切的「岩板」形状（扫码按钮、老带新卡片），头像做成岩点形状。

## 2. 最初的需求

小程序：

1. 购买期限卡（月卡、季卡、年卡）、次卡（10 次、20 次）、私教课、团课。
2. 会员扫码入场；次卡可以分享给别人，做成小程序链接发到微信，对方点开领取后进自己的卡包，在前台扫码入场。
3. 期限卡会员每月有一次老带新权益，也是做成小程序链接发给朋友领取；领取人只要在分享人扫码签到的当天扫码，就能免费入场。
4. 约私教、报名活动、参加团课。

管理后台：数据看板、统计和财务信息、发布课程和活动。

后来新增：**定线分析**。每家店大约每月换一次线，想对比每家店每批线带来的客流，判断这批线的吸引力和质量。

## 3. 已经定下的决定

### 规则（原型里已实现，正式版的规则在 `packages/core`，有单测）

- **入场**：会员用小程序扫前台的二维码（还没跟客户确认，见第 6 节）。有多张卡时让会员选，期限卡优先，期限卡不扣次。
- **同一天再次入场不重复扣次。**
- **次卡分享**：从原卡里拆出几次送给朋友，送出时立即从原卡扣除；朋友领取后得到一张「好友送的次卡」，有效期和原卡一致，不能再转送。不能领自己发出的分享，一个分享只能被领一次。
- **老带新**：只有期限卡会员能发，每个自然月 1 次；体验券当月底前有效；**邀请人当天先扫码入场后，领取人当天才能用**。领取人先扫码会被拦下，并提示要等邀请人入场；邀请人入场后，领取人的小程序会收到提醒。
- **当日保险和风险告知书**（原型里的做法，待确认，见第 6 节）：扫码入场的确认页里一起买当日保险，和卡一起付款；第一次入场时在线勾选同意《攀岩运动风险告知书》、填一次身份证号，以后不用再签。目的是前台不用再收纸质单。保险当天 24:00 前有效，同一天再次入场不用重复买。保费算代收，不计入馆里营收。
- **去掉了「馆里现在多少人」**：没办法知道会员什么时候离场（除非拿定位），所以小程序首页和后台都不显示在馆人数。后台原来的位置换成了「今日约课」。
- **今日入场的对比**：和上周同一天的同一时段比，不跟上周全天比。

### 定线分析的口径

- **换线前** = 换线日前 14 天的日均入场；**换线后** = 换线日后 N 天（7 / 14 / 28 可选），碰到这家店的下一次换线就截止。
- **提升** = 换线后 ÷ 换线前 − 1。
- **同期其他分馆** = 另外两家店在相同日期里的变化，代表节假日、天气、季节这些全馆共有的影响。
- **净提升 = 提升 − 同期其他分馆**，比较批次和店的时候看这个数。
- **热度持续** = 扣除同期其他分馆后，客流回落到换线前 +5% 以内用了几天。热度回落的店会提示「可以安排下一批」。
- 所有数字都按星期几校正（周末本来人多）。
- **已知局限**：三家店都每月换线，「同期其他分馆」里也混着它们自己新线的热度，所以净提升更准确的意思是「比同期其他店多涨了多少」，是相对比较；要积累几个月的数据才稳定。
- **正式版需要的数据**：入场记录要带店（每家店前台放不同的二维码）；后台登记每次换线（店、日期、区域、主题、定线员、线路数、难度分布）。回访率、从其他店过来的人次，从入场记录里算。

### 技术

- 小程序：uni-app + Vue 3；后台：Vue 3 + Vite；仓库：pnpm workspace + Turborepo。
- uni-app 锁定 Vue 3.4.21 和 Vite 5.2.8，后台用 Vue 3.5 和 Vite 8；共享包按两个版本都能用来写。
- 按岩馆打包：环境变量 `GYM` 选 `gyms/<id>`，代码里 `import gym from '@gym'`；`pnpm build:gym benchmark` 同时打出小程序和后台。细节见 README。
- 小程序 AppID 目前是微信开发者工具的测试号 `touristappid`，正式发布前换成馆方的。
- 后端还没开始；`packages/api` 里的接口路径是约定稿，后端打算放在 `services/` 下。

## 4. 当前进度

### 原型（`prototype/`，纯 HTML，给客户演示用）

- 两部手机并排：左边是年卡会员阿杰，右边是第一次来的小鹿，共用一套数据，可以真的走一遍次卡分享和老带新。
- 小程序：首页、购卡（模拟微信支付）、扫码入场、卡包、次卡分享和领取、老带新、约团课、约私教、活动报名、我的（攀爬日历、预约、分享、订单）、微信聊天里的小程序卡片。
- 扫码入场：确认页 = 选卡 + 当日保险 + 风险告知书（第一次才要签），一次微信支付；入场页、「我的 → 保险与告知书」能看到保单。后台「入场与分享」每条入场记录标了是否投保，并显示当天代收保费。
- 管理后台：数据看板、财务、定线分析、会员、课程排期（可发布团课）、活动（可发布活动）、入场与分享、卡种与价格（改价、下架）。在小程序里的操作会实时出现在后台；后台发布的课程、活动、改的价格，小程序里马上能看到。
- 数据看板可以切换「全部门店 / 滨港店 / 汇聚店 / 环球港店」；看全部门店时有「门店对比」；有「新客从哪来」（本月第一次来馆的人按来源分，以及其中办卡的人数）。团课、入场记录都标了门店；小程序两部手机的演示操作都算在滨港店。
- **问数据（演示）**：后台右下角「问数据」，看板「新客从哪来」和定线分析页上也有「问一问」。能回答五类问题（上个月哪个活动新客占比最高、近 6 个月哪批定线探馆频率最高、上个月哪家店营收最高、这个月老带新、超过 30 天没来的期限卡会员），会先反问「新客」的口径，回答里有结论、表格、口径、可展开的查询过程和跳转按钮。原型里没接大模型：用关键词识别问题类型，用和看板同一套数据算答案（`prototype/js/ask.js`）。
- 左侧有 8 条演示路线，点「从这里开始」直接跳到对应页面；右上角「重置演示」清空所有操作。
- 门店维度是把全馆模拟数据按固定比例拆出来的（`prototype/js/stores.js`）；会员页、财务页、小程序里的大部分页面还没有按店区分。

## 5. AI 问数据的方案（还没开始做正式版）

- **判断**：第一期不需要；等有几个月真实数据、老板开始反复问看板上没有的交叉问题，或者要卖给多家岩馆时再做。现在要做的是把指标口径集中定义在代码里、数据模型里带上门店和会员首次到店时间。
- **做法**：不让大模型直接写 SQL。大模型只负责理解问题、调用几个固定工具：`find_entities`（把「夜爬」「上个月滨港店那批线」对应到具体记录）、`query_metric`（查预先定义好的指标，可分组、过滤、排序）、`get_definition`（返回口径）。数字由指标层算（建议放在共享包 `packages/metrics`，看板和 AI 共用，保证数字一致）。
- **防护**：门店和岩馆范围由后端按登录身份加，模型改不了；数据库只读、限时、限行数，按岩馆行级隔离；工具只返回汇总数，不返回会员名单；查不到就说查不到。
- **产品**：回答 = 一句结论 + 小表格 + 口径 + 查询过程 + 跳到对应页面；问题有歧义先反问（比如「新客」指第一次来馆还是第一次办卡），选过的口径记住；推荐问题、点赞点踩、记日志。
- **评测**：上线前准备 30–50 个真实问题和标准答案，用测试数据库跑，换模型、改提示词前都跑一遍。
- **模型**：服务器和公司在中国大陆时用国内模型（通义千问、DeepSeek、智谱、豆包等都支持工具调用）。模型调用包一层自己的接口，以后换模型只改一处。会员数据只送汇总数，注意个人信息出境和生成式 AI 服务的备案要求。
- **成本**（阿里云百炼北京地域原价，2026-10-17 查自 help.aliyun.com/zh/model-studio/model-pricing）：qwen3.8-max 输入 12 元/百万 Token、输出 36 元；qwen3.7-plus 输入 2 元、输出 8 元（当时限时 8 折）；qwen3.8-flash 输入 0.8 元、输出 2.7 元。按一个问题约 1.5 万输入 Token、1500 输出 Token（复杂问题约 3 万 / 4000）估算，每周 10 个问题（每月约 43 个）：qwen3.8-max 每月约 10–22 元，qwen3.7-plus 约 2–4 元，qwen3.8-flash 约 1–2 元。新用户每个模型有 100 万 Token 免费额度（90 天有效）。这个用量下模型费用可以忽略，选模型看评测准确率。

## 6. 等客户确认的问题

1. **入场方式**：会员扫前台的码，还是前台扫会员的码？（每家店前台放不同的码，入场记录就能带上门店）
2. **老带新的「当天」**：现在是体验券当月有效，哪天邀请人入场，领取人当天就能用。还是只能在分享的当天用？
3. **价格和规则**：现在全是占位（见第 7 节）。还有：期限卡能不能冻结、多少天；次卡和课包的有效期；团课、私教的取消规则（原型里写的是团课开课前 2 小时、私教提前 12 小时）。
4. **会员卡是否三家店通用**：这会影响入场规则，也影响定线分析（跨店来访）。
5. **三家店的真实信息**：每家店的区域名称、定线员、客流和营收大概的比例（原型里设成滨港店 44%、汇聚店 32%、环球港店 24%）。
6. **账号归属**：小程序和微信支付商户号要用馆方的营业执照注册，开发方只拿开发权限；认证费、支付手续费由谁承担。
7. **预付卡合规**：当地对健身类预付卡有没有要求（单卡金额上限、冷静期、资金存管）。
8. **现有数据**：会员名单、各卡剩余次数和到期日能不能导出，用来评估导入的工作量。
9. **当日保险**：现在前台签的是什么（告知书、保险单，还是两样都有）；是不是每次入场都必须买；保费多少、谁出（会员付，还是期限卡里含）；跟哪家保险公司、怎么接（保险公司的小程序或接口，还是馆方买团体险）。馆方自己卖保险可能需要代理资质，要问清楚；投保需要会员的身份证号，属于敏感个人信息，要单独告知和同意。告知书文本要馆方提供或请律师看过。
