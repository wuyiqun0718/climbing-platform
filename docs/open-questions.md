# 待拍板的问题

只记录，不决定。每条写清楚现状、为什么要定、有哪些选项；定了以后在条目下面写结论和日期，再去改代码。

要问馆方的业务问题（入场方式、价格、保险等）在 `docs/project-context.md` 第 6 节，这里记的是做后台时冒出来的产品问题。

## 门店后台（来自 `docs/ui-review/eval-2.md`，2026-10-23）

### 1. 「活动」页没做完，导航里要不要先藏起来？

- 现状：三个角色都能点进去，看到「活动的报名、签到还在做」的占位页。
- 选项：藏起来更干净；留着，客户演示时能看到这一项在规划里。

### 2. 前台能不能看看板上的「新客从哪来」「老带新转化」？

- 现状：前台能看这两块，营收已经对前台隐藏。
- 为什么要定：这是经营数据，馆长可能不想让前台看到。要藏的话接口和页面都要按角色裁。

### 3. 前台看别的店的会员时，要不要显示真实门店名？

- 现状：接口只给前台本店的名字，别店的归属门店、首次到店门店都显示「其他门店」。
- 为什么要定：前台帮别店会员登记入场时，可能需要知道会员是哪家店的。选项是只读给出全部门店名，或者保持现状。

### 4. 「7 天内到期」要不要「提醒续费」按钮？

- 现状：看板列出 7 天内到期的期限卡会员，没有操作。原型每行有「提醒续费」。
- 要定：提醒方式（小程序订阅消息 / 短信 / 前台打电话后记一笔），接口也还没有。

### 5. 看板缺的图要不要做？

- 现状：原型有近 30 天营收堆叠柱状图、本月营收构成、今日分时段入场、今天的团课、实时动态，后台还没有。
- 选项：引入图表库，或者手写 SVG；第一轮 UI 验收定过先不引入图表库。

### 6. 前台平板入口放在哪？

- 现状：第二轮先放在侧栏导航最后（「前台平板 ↗」，只给店长以上，新开一页）。
- 选项：保持；放到设置页；不放入口，只把链接发给店长。改起来都很小。
