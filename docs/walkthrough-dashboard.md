## 这次直接修的

1. **权限：前台在看板上能看到本月营收。** 前台看不了财务页，但 `GET /admin/dashboard` 照样返回营收。改成没有财务权限的返回 `monthRevenueCents: null`，看板显示「—」（测试）。
2. **逻辑：前台卖单次票被记成「次卡」，还被当成「办卡」。** 财务按品类统计时单次票应该单独算；而且卖单次票会改会员的办卡日和归属门店，跟看板「单次票不算办卡」的口径不一致。core 的 `order.ts` 加了 `productRevenueCategory`，`countsAsCardPurchase` 改成按卡种判断，单次票不算（单测）。
3. **示例数据：卡种里没有单次票。** 补了一个「单次票」（99 元，当天有效），路线 3 要用。

## 没修、列出来的

### 逻辑 / 数据

- **看板首屏的营收、今日入场、上周同期、有效会员还是 mock 里写死的示例数。** 前台登记、扫码入场以后这几个数不变；「今日约课」已经按预约实时算。真后端要按订单、入场记录、卡来算，mock 要改的话要动看板的几条测试。上周同期要用到入场时间，示例入场记录没有时间。
- **小程序分支的接口在后台 mock 里只有一部分。** 小程序课表、教练列表、会员扫码入场这几个在后台 mock 里有，跟后台读同一份数据；会员下单、送卡领卡、约课还没有。合并两个分支时要把小程序 mock 改成读同一份数据。
- **分享状态有两套同义的定义。** 小程序 `share.ts`（`shareDisplayStatus` / `SHARE_STATUS_TEXT`）和后台 `shareRecord.ts` 意思一样，合并时统一，用小程序的名字。
- **平板上没有二维码图片。** 约定由后端在 `GET /desk/qr` 里返回图片；前端要自己画的话得加二维码库（要动 lockfile）。
- **会员没有头像。** 平板实时列表的头像都是空的，显示名字首字。

### 权限（都是 `permissions.ts` 里的占位，等馆方定）

- 只管一家店的店长能改全馆共用的东西：卡种价格、团课课程。要不要只给老板，等馆方。
- 会员列表全店可见（`MEMBERS_VISIBLE_ACROSS_STORES = true`），前台能看到别的店的会员。
- 前台能撤销入场、帮会员取消团课、签到（已定或占位）；不能退款、调整、导出、排课、绑平板。
- 只做教练的员工（Max）用的是前台角色，后台里能看到会员列表、入场记录等前台能看的页面；教练要不要单独一个角色，等馆方。
- 操作日志：老板看全部；店长只能按自己的店看，看不到卡种、员工这类全馆的日志。

### UI（只记不修，没在浏览器里点过）

- 各页面没有在真浏览器、平板尺寸下走过；表格在窄屏下会不会挤，没看。
- 私教时间轴没有原型里「刚约的那节有黑框」。
- 平板页二维码处现在显示码的文字内容。
